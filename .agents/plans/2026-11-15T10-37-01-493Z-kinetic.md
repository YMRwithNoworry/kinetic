# KINETIC 性能极限优化与行为保护

## 目标与假设

在不改变已支持模型外观、动画/联动行为、协议语义、资源生命周期和最低设备基础可用性的前提下，系统性降低客户端帧耗时、动画/渲染 CPU 成本、分配与 GC 压力、加载延迟及服务端 MSPT。优化按实测瓶颈排序；GPU compute 是候选主路径，不预设它必然胜过 CPU SIMD。保留可完整使用的 CPU renderer，按设备能力与功能覆盖选择路径。所谓“不影响现有功能”以契约测试、CPU/GPU 等价、真实游戏验收和可回退为验收标准，不承诺对所有模组组合与驱动绝对零风险。

## 关键发现

- 主渲染链路为 Java 动画/状态 → native CPU bake/extract/render → Java/Minecraft 顶点提交，GPU draw 归 Minecraft/Iris 所有：[渲染架构](docs/architecture/rendering/README.md)、[帧执行](docs/architecture/rendering/frame-execution.md)。
- GPU Compute Renderer 尚未实现；已有资源生命周期、同步、独立 ABI、CPU fallback 与一致性入口条件：[GPU 未来设计](docs/future/gpu-compute-renderer.md)。CPU cache/AoSoA 不能直接作为 GPU ABI。
- 热点候选已有证据但缺端到端基线：动画求值频率上限不减少每帧 `ModelState::Extract`；本轮测了一个动态 Molang binding 的单表达式微基准，但完整模型/controller 热路径与真实分布仍未测；native 调度按 `CubeGroup` 数近似均分、透明排序和共享 scratch 有串行边界：[动画状态](docs/architecture/animation/entity-and-frame-state.md)、[动画问题](docs/status/known-issues/animation.md)、[渲染问题](docs/status/known-issues/rendering.md)。
- 已有 opt-in 的 native extract 微基准及简单动画吞吐测试：[NativeExtractCostBenchmarkTest](src/test/java/com/kinetic/natives/render/NativeExtractCostBenchmarkTest.java)、[ProneActionThroughputTest](src/test/java/com/kinetic/client/animation/ProneActionThroughputTest.java)。尚无覆盖真实多实体、多 pass、Molang、完整 draw 与 GPU 同步的统一基线。
- 性能排序受主循环保护、资产传输让行和既有设备策略约束；服务端目标是软目标，不是任意负载 SLA：[workload-budget](docs/product-decisions/decisions/workload-budget.md)、[device-quality](docs/product-decisions/decisions/device-quality.md)、[性能验证政策](docs/governance/verification-policy.md)。
- 当前仓库不包含 native C++/GPU 实现源码，仅有 Java wrapper、测试和内嵌 native 二进制。GPU/native 实施需要定位并纳入配套 native 工程：[native 构建指南](docs/build.md)、[native Gradle 配置](gradle/native.gradle)。

## 实施步骤

1. **建立可复现基线**：定义固定场景和模型规模，分别测量冷/热加载、动画/Molang、Extract、native Render、Java 提交及多实体多 pass；客户端记录 p50/p95/p99 帧耗时、阶段 CPU 时间、分配/GC、顶点和任务分布，服务端记录 MSPT、队列延迟、资产发送与 gameplay 流量。参考设备覆盖高端与基础设备，100 人服务端场景按既有软目标观测；高成本压测仅用于容量诊断。只在诊断/基准模式开启采样，避免给常规热路径增加显著开销。
2. **先消除已测 CPU 热点**：按基线优先实现 Java/Molang 去重复求值、骨骼姿态复用/采样插值、JNI 交接与临时分配削减、native schedule 按真实工作量均衡、缓冲容量/透明排序成本优化。每项独立提交基准和语义测试；动画降频/插值须保留每帧头部朝向、controller/action 触发时序、各 RenderContext 隔离及累计逻辑时间。只调整有可重复收益的路径。
3. **GPU 可行性与原型**：在配套 native 工程验证 Minecraft 1.20.1 Forge 的 OpenGL/驱动能力、Iris/shader pack 接入和目标设备覆盖。仅当基线证明 CPU 变换/顶点输出是主要瓶颈时，做独立版本化的最小完整 compute 路径；静态数据按 render target 上传，逐帧只传必要姿态，compute/draw 之间使用 barrier/fence，避免每帧全量读回 CPU。Java 继续持有模型选择、纹理、lease 和 GPU 资源生命周期。
4. **按完整 draw 做能力选择和回退**：每次 draw 原子选择 GPU 或 CPU，未支持的 pass、shader、功能组合、设备能力或 GPU 错误完整走 CPU，不允许半模型混合输出。附着点返回 Java 所需的小型结果。先 opt-in/开发配置验证，覆盖闭环后再按既有配置治理决定启用策略；不得移除 CPU renderer。
5. **守住功能契约并记录结果**：对普通/反向 cube、部分面、透明排序、纹理 alpha、非均匀缩放、normal/tangent、PBR、Vanilla/Iris/shadow、GUI/第一人称/level、模型热切换、扩展接入和失败回退建立 CPU 对照 golden/容差测试及游戏内场景。动画记录跨帧骨骼/事件与动作触发结果；网络及服务端验证 gameplay 流量优先。全量跑 `./gradlew test`、`./gradlew processorTest`、`./gradlew build`，并做真实 Forge A/B 与目标设备性能对比。更新 GPU、架构、known-issues、状态和复杂度文档；若需改变产品契约，先由 human 仲裁。

## 验收与风险

- 功能验收以现有测试全通过、关键行为 golden/容差通过、目标场景无新增视觉/动画/网络回归、失败时可完整回 CPU 为准；GPU 路径达到可重复的端到端收益后才值得默认启用。
- 性能报告必须给出硬件、驱动、Minecraft/Iris/shader、模型规模、玩家数、冷/热状态及基线/优化后分布；微基准不能单独证明游戏内收益。不能达到收益或超出内存/功耗预算的 GPU 原型应停止，不牺牲基础设备可用性。
- 最大风险是 native 源码不在当前工作树，且 GPU compute 与 Minecraft/Iris 管线、shader reload、设备丢失和移动/老旧设备的兼容与功耗需要实机验证。GPU 原型依赖配套 native 工程；如果该工程不可用，先完成基线和已测 Java/CPU 优化，不用修改二进制替代源码维护。

## 不采用

- 不盲目将整个 renderer 一次性替换成 GPU compute：会扩大驱动、shader pack、资源回收与透明语义风险，且当前 GPU ABI 尚不存在。
- 不默认开启全局 GPU 背面裁剪或以 LOD/删面降低工作量：已有模型和第三方枪包依赖不完整面及反向几何语义。
- 不依据单次微基准或理论吞吐重写线程池、无限增加后台并发或常驻复制资源；这些做法可能把模型成本转移成主循环饥饿、内存压力或 gameplay 网络阻塞。

## 执行调整（2026-11-15）

当前工作树是 Java 模组工程；`D:/code` 下没有 KINETIC 配套 native 源码工程，仓库仅提供预编译 DLL/SO。当前环境可运行 JDK 17 和 Windows DLL 微基准，但没有固定 Forge/Iris A/B 场景、目标设备矩阵或 100 人服务端环境。因此本次继续完成可复现的 Java/native-binary 阶段诊断，只在测量确认且语义可守护时做 Java 改动；不改写 native 二进制，不实现 GPU，不把微基准视为游戏内收益。GPU 原型与真实游戏/服务端验收保持未完成，需在相应工程和设备环境补做。

## 本轮验证结果（2026-11-15）

- Java 视图复用、Extract/native-render 微基准、动态 Molang binding 测试及相关文档更新已完成。
- `processorTest --offline` 与 `build -x test --offline` 通过。正常 `build` 已完成编译和打包任务，但被全量 `test` 的 22 项失败阻断；共 799 tests、11 skipped。20 项失败依赖未配置的 `KINETIC_AUDIO_FIXTURE_DIR`，1 项是 Windows stderr 换行断言，另 1 项是 `ModelExporterTest` 将 8.3 短路径与 `toRealPath()` 长路径直接比较的测试问题；详见 `docs/status/verification-ledger.md`。
- 文档自检因环境没有可用 Python 解释器而未执行；`git diff --check` 通过。GPU/native 源码实现、Forge/Iris A/B 与服务端 MSPT 验收仍未完成。
