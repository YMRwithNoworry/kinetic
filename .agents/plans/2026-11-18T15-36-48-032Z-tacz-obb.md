# TaCZ 玩家模型 OBB 命中区（不改原版物理）

## 已确认边界
- 只改 TaCZ 子弹对玩家的命中检测；Minecraft 玩家物理碰撞箱、移动/阻挡逻辑、TaCZ 对非玩家实体的处理都保持原样。
- TaCZ 缺失、模型/姿态数据不可用、不受支持或 OBB 计算失败时，沿用 TaCZ 原有 AABB 命中路径；不能丢失命中功能或阻断游戏。
- 姿态由服务器可重建的可信输入产生；不接受客户端上传任意骨骼矩阵或 hitbox。
- 这属于玩法行为的 TaCZ 专项例外，需要同步改 Root Authority，并精确记录例外范围、理由和降级边界；不扩张为通用模型物理或其他武器的碰撞规则。

## 实施步骤
1. **闭合产品契约与 TaCZ 版本边界**
   - 按仓库治理规则更新 `docs/product-decisions/decisions/visual-gameplay-boundary.md` 与 `mod-integration.md`：保留原版物理 AABB，仅为 TaCZ 玩家弹道命中加入服务端验证的模型 OBB 窄相；写清不适用范围和 AABB 回退。
   - 先核对构建当前固定的 TaCZ 依赖及实际运行版本；已有反编译资料版本不同，不能直接据此落 Mixin。沿实际源码/字节码确认候选实体收集、历史 hitbox、射线检测、命中点和 headshot 全链路，再决定最小接入点。TaCZ 是可选依赖，缺失时不得加载其类型。
2. **定义可信几何与姿态支持集**
   - 从服务端已经裁决的模型选择和服务端可用的已验证模型数据生成有限数量的身体区域 OBB；先厘清服务端是否能取得完整几何、每个区域如何映射到骨骼、缩放/旋转和模型更新如何处理。
   - 姿态仅从服务器游戏状态及能够在服务端确定性重建的姿态来源生成；不得把客户端渲染矩阵、未验证动画状态或缺失的骨骼姿态默认为可信。对无法确定性重建的自定义动画/模型、缺失头部区域、越界/非有限变换或复杂度超限，整组 OBB 判为不可用并回到原 AABB，不裁剪为不完整 hitbox。
   - 在原版实体 AABB 之外只扩展 TaCZ 的弹道候选收集边界（若源码链路需要），绝不改 `Entity` 物理 bounding box。用模型/姿态版本切换清空并重新建立历史样本。
3. **实现服务器 OBB 与 TaCZ 窄相（前置门槛：存在可证明的支持姿态）**
   - 只有确认服务端可以取得并完整验证模型几何、且该姿态可由服务端已有权威状态确定性重建时，才实现 bounded OBB、历史姿态和 TaCZ 接入。服务端没有可信姿态 owner 时，不添加空接入、静态 AABB 冒充模型 OBB，或依赖客户端骨骼矩阵；保持 TaCZ 原 AABB，记录阻塞并停止运行时代码步骤。
   - 在门槛成立时，纯 Java OBB 逻辑不依赖 TaCZ；由服务器 tick 更新缓存形状，子弹路径只做有界 broad/narrow-phase 测试。
   - TaCZ 接入只在已核验依赖版本的最窄安全点进行，并让回溯命中使用同一历史姿态快照；命中点及 headshot 语义一致。注入不兼容、快照过期、reload/登出/维度切换、算术失败均局部回退。
   - 可选依赖通过早期安全的模组存在检查启用专用接入；非 TaCZ、非玩家及其它弹药路径保持原样。
4. **建立适用的回归与验证**
   - 若 OBB 门槛成立，按原计划添加 OBB 相交、多区域/头部归类、候选覆盖、历史快照与可选依赖隔离测试。
   - 若当前不存在可证明姿态子集，不写无调用者的数学测试或虚构 runtime integration guard；保持现有 AABB 行为，并运行项目既有测试与文档检查。Forge 服务端 + TaCZ 双客户端实测仅在实际集成实现后执行；未实测的版本与姿态明确标记为未验证。
   - 验证命令：相关 Gradle 测试、`./gradlew test`、`./gradlew processorTest`、`./gradlew build` 与 `python docs/tools/check_docs.py`。
5. **同步架构与支持记录**
   - 新增 TaCZ hit-detection 架构说明，准确记录已解析版本的现行 TaCZ 命中链、KINETIC 当前没有 OBB/历史姿态 owner、现行 AABB fallback；更新当前支持/验证记录及复杂度地图。只有最终确实扩展玩家状态协议或 server animation owner 时才更新对应网络/动画文档；不预先把设想写成现状。

## 验收条件
- 原版玩家碰撞箱逐路径不变；非 TaCZ 和非玩家行为不变。
- OBB 路径只对服务端可重建、验证完整且在边界内的姿态启用；其他情况原子切换为 TaCZ 原 AABB 路径。
- TaCZ 回溯命中、命中点及 headshot 判定与同一历史形状一致；异常/切换过程不产生陈旧 hitbox。
- Optional dependency isolation、文档与自动化测试通过；实机结论与实际测试组合匹配。

- 已将 TaCZ 专项产品例外、适用范围和原 AABB 降级写入 Root Authority；新增 TaCZ 当前命中链说明、支持状态与复杂度地图的“无生产机制”记录。OBB 运行时代码、专用单测及实机验证因此没有实际实现对象，不作通过或支持声明。
